# ALB 0.4.2 两轮代码审查关闭记录

## 文档角色

- 角色：0.4.2 两轮独立代码审查的关闭记录。
- 允许更新：已执行范围、真实发现、修复提交、复验命令和最终严重度状态。
- 禁止更新：制造无意义发现、把未执行检查写成通过或替代正式机器验收。
- 事实来源：Git diff、pytest、分层 mypy、feature manifest 和正式候选。

## 第一轮：数值与 API

- 审查日期：2026-07-24。
- 审查输入：0.4.1 实现候选 `a26435e...` 到初始 0.4.2 修复
  `f063731` 的完整 diff。
- 独立关注点：合法路径逐元素一致、拒绝发生在求解前、adapter local dt 与
  物化组件一致、异常类型和 failure snapshot 完整。

发现并关闭两项 P2，没有 P1：

1. `R1-P2-01`：复数 `time_grid` 会在 `np.asarray(..., dtype=float)` 中丢弃
   虚部并可能产生 warning，而不是在轨迹 runtime 创建前稳定拒绝。修复为先
   检查复数输入并抛出 `TypeError`；新增 pre-runtime 计数测试。
2. `R1-P2-02`：`matrix_rank()` 或 `cond()` 的 SVD 诊断异常没有稳定错误边界，
   会泄漏原始 `LinAlgError`。修复为 `CalculationError`，snapshot 保存双轨迹、
   复位移矩阵、目标/实际频率、Nyquist 和异常类型。

修改位置复读后未发现新的 P1/P2。第一轮复验：

```text

V4P2 required nodeid：48 passed
分层 mypy：23 个 strict target 通过；实现层 363 条、85 组，基线未扩大
```

成功路径合同继续对 0.4.1 参考使用 `assert_array_equal`，未重建参考。

## 第二轮：生命周期、事务与发布

- 审查日期：2026-07-24。
- 审查输入：第一轮关闭提交 `bf256b5` 后相对 0.4.1 的新完整 diff。
- 独立关注点：exactly-once、step 0/最后一步、recorder close、Windows 原子
  替换、临时文件、公共协议、文档、manifest 和 wheel。

发现并关闭两项 P1、两项 P2：

1. `R2-P1-01`：simulation 对象在成功或失败后仍可再次调用 `run()`，会绕过
   “一次性、不可恢复”边界并重放物理会话。新增私有 one-shot 门禁；第二次
   调用在构建 coupling 前抛出 `SimulationError`，recorder 和物理步骤计数
   保持不变。
2. `R2-P1-02`：snapshot/manifest 的临时文件清理失败会替换最初 I/O 异常。
   新增持久化次级错误收集器，清理、强制保留、manifest retry 和 recorder
   close 错误只写入 failure snapshot，最初异常继续作为 cause 和
   `error_type`。
3. `R2-P2-01`：高层 simulation 重建 failure snapshot 时丢失 coupling 已密封
   的 pre-commit 数值诊断。现在嵌套保存 sanitized coupling values/metadata，
   同时保留高层 partial history 和提交状态。
4. `R2-P2-02`：原门禁没有覆盖 manifest replace、最后一步 post-commit 的
   disk-stream 发布，以及成功/失败后的 one-shot 重放。补充失败注入和计数
   测试；最后提交快照只写一次，manifest 标记 incomplete，临时文件无泄漏。

修改位置复读后未发现新的 P1/P2。第二轮复验：
