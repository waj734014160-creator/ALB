# ALB 0.2.0 P2 架构欠账收敛报告

## 文档角色

- 角色：P2 架构改造的耐久审计报告。
- 目的：逐项说明 P2-1 至 P2-12 的完成标准、实现位置、行为保护和剩余边界。
- 允许更新：本轮最终候选提交、正式验收数字、证据路径和已核实的限制。
- 禁止更新：外部训练实时状态、论文计算进度、未执行的通过结论和原始日志正文。
- 事实来源 / 相关文档：`docs/current_state.md`、`docs/interface_architecture.md`、
  `refs/native_control_lifecycle_reference_v9.json`、Git 提交和本文件列出的测试。

## 结论

P2-1 至 P2-12 的实现边界已经收敛。此次工作没有改写既有 v1-v8 参考，也没有借架构拆分修改
Reynolds、热耦合、控制、转子、耦合或 ALBNN 方程。原生控制生命周期以新增 v9 参考保护；其余
拆分通过既有精确回归、接口测试、状态转换测试、分层 mypy 和最终 detached 发布验收共同保护。

“完成”不表示所有历史模块已实现 strict mypy 零诊断。完整四个领域 namespace 已进入门禁，
其中新边界使用 strict 零错误，旧算法体使用精确的文件加错误码计数基线；任何新增类型债务都会
失败，既有诊断将通过后续小提交只减不增。这一做法避免为了形式上的一次清零而改动数值实现。

## 明确保留的兼容边界

- `ALB.control.controllers`、`ALB.config._models`、`ALB.systems.alb.assembly` 只供包内和迁移期
  重导出，不是新的推荐导入路径；机器 import map 指向实际领域模块。
- `LegacyControllerAdapter` 只服务无法一次升级的外部自定义控制器，不允许系统装配再次直接识别
  “计算型 output”协议。
- `ServoValve2.solve()` 保留为迁移别名，但不会造成第二次推进。
- 221 条 mypy 历史诊断是显式锁定的清理队列，不是忽略目录；新增文件或诊断漂移会使门禁失败。
- 发布 runner 中 0.2 专用的关键 nodeid 集合与精确 pytest 策略仍属于版本策略；通用执行阶段已从
  大脚本移出。fresh 工具的传递依赖哈希/wheelhouse 是供应链加固工作，不属于 P2-12 的阶段拆分
  完成条件。
