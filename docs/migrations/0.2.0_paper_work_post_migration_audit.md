# PAPER_WORK 的 ALB 0.2 迁移后审计

## 文档角色

本文是 `0.2.0_external_consumer_audit.*` 的迁移后证据，不覆盖只读 v1
审计。它记录 PAPER_WORK 消费者源码迁移、可恢复快照、模型 package 校验和
剩余边界；不保存论文计算进度，也不修改既有论文数据和输出。

## 结论

- PAPER_WORK 不是 Git 仓库，因此没有虚构迁移分支或 commit。
- 修改前已在 `refs/alb_0_2_consumer_migration_v1/` 保存 27 个 declared 文件和
  2 个动态 helper 的源码副本、原始 SHA-256 与 manifest。
- 25 个 direct 文件已改写；2 个 declared transitive 文件不含直接旧 import，
  源码保持不变；审计遗漏的 2 个动态 helper 一并改写。
- 29 个文件的旧平铺 ALB import 数量为 0。
- 历史 remote payload、论文数据、图件和输出均未修改。

## ALBNN 模型边界

- M0031 和 M0035 消费者改为读取现有 `package_v0_2`。
- 加载统一使用 `load_albnn_package(..., trust_pickle=True)`，明确只信任本地已校验
  package 中的 pickle scaler。
- 两个 package 的 manifest schema 和全部 artifact SHA-256 均通过校验；运行时不再
  直接引用 `best_albnn.pth`、`scaler_X.pkl`、`scaler_y.pkl`。

## 验证

- 29/29 文件以 UTF-8 解析 AST 通过。
- 24 个带 `__main__` 入口保护的模块完成真实 import smoke。
- 4 个任务脚本存在顶层执行，连同 remote wrapper 共 5 个文件只做 AST/import-node
  检查；remote wrapper 另行通过 `--help`。
- M0031/M0035 package 均通过 manifest 校验和可信加载 smoke。
- 机器可读逐文件新哈希与验证摘要位于
  `docs/migrations/0.2.0_paper_work_post_migration_audit.json`。

## 保留边界

- 四个顶层执行脚本仍需单独增加主入口隔离，之后才能纳入 import smoke。
- 两个 M0035 脚本仍使用 `BaseSimpleModel/FakeOf` 的内部代理形态；DTO block 生命周期
  迁移需要单独参考与数值回归，未在本次 import 迁移中强行改写。
- legacy shared JSON5 当前由 `ALB.infrastructure.config_io` 展开；nested 0.2 schema
  的直接加载链尚未完成，因此没有用不完整的 `alb12.json5` 迁移结果替换运行配置。
- 历史 remote payload 不做原地改写；下次运行前应从已迁移源码重新构建 payload。
