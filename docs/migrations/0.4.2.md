# ALB 0.4.2 审阅缺陷修复说明

## 文档角色

- 角色：0.4.1 到 0.4.2 的稳定修复与发布边界说明。
- 允许更新：0.4.2 输入域、时间步、失败原子性、数值合同和验收入口。
- 禁止更新：临时测试日志、未执行的通过结论、外部实时状态和核心算法替换。
- 事实来源：0.4.2 feature manifest、冻结参考、两轮审查记录和正式验收报告。

## 版本边界

Python 包版本升级为 `0.4.2`。JSON5 `schema_version` 和 surrogate package
格式继续使用 `0.4.0`，现有 0.4 配置和模型无需迁移。`v0.4.0`、`v0.4.1`、
对应 wheel、manifest、参考和正式报告保持历史不变。

本补丁只收紧非法输入域、统一真实时间尺度并修复仿真失败原子性。合法输入继续
使用 0.4.1 的静平衡、`recognize_kc()`、FFT 和液膜核心算法，不以新算法替代。

## 数值输入边界

- `dynamic_coefficients()` 在创建轨迹 runtime 前要求有限、严格递增、均匀且
  至少含两个点的时间网格。目标频率必须为有限正数、不超过 Nyquist，并命中
  非 DC 的 `rfftfreq()` bin。
- 正反涡动复位移矩阵必须有限、满秩，条件数不得超过
  `1 / sqrt(float epsilon)`。拒绝信息通过 `CalculationError` 携带目标频率、
  实际 bin、Nyquist、双轨迹和矩阵诊断。
- `find_equilibrium()` 拒绝精确零载荷，因为既有收敛判据使用载荷模长归一化。
  非零载荷仍使用原相对残差算法。

## 时间步契约

`RotorProtocol` 明确要求只读 `dt`。`SimulationConfig` 直接从协议读取转子时间
步；第三方转子缺少该属性时在配置阶段失败。

每个 mount 的 bearing-local 期望步长由其 unit adapter 对全局
`StepContext` 的真实转换得到。无 adapter 时才与全局量纲步长数值相等。构建器
在创建任何物理 runtime 前递归检查根轴承、物化控制器、阀、热模型以及 inline、
文件引用和多层 `MultiPad` 子配置。独立 `build_bearing()` 与 simulation 共用
同一检查。

## 仿真失败与磁盘事务

高层仿真保持一次性、失败即终止的语义。严格 recorder 或 observer 在提交后
失败时，facade 从 coupling ledger 和只读 output 取回已经提交的真实步骤：

- 不重复物理计算，不自动重试 pending record，也不继续后续步骤；
- partial result 包含该提交，`metadata["complete"]` 只描述请求的物理步骤是否
  全部提交；
- `history_complete` 和 `post_commit_complete` 分别描述历史发布和提交后处理；
- recorder 通过 `end_run(allow_incomplete=True)` 封存，实际 close receipt、
  pending key、observer failures 和次级异常写入密封 failure snapshot。

`disk_stream` 在目标目录写同目录临时文件，flush 和 fsync 后原子替换。只有替换
成功才发布 record 与 retained index。`history.json` 使用相同事务边界。失败
处理可对最后提交快照强制保留一次；清理、重试、manifest 或 recorder close 的
次级失败只进入诊断，不覆盖最初异常。
