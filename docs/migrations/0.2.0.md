## 迁移结论

`0.2.0` 是命名空间优先的破坏式版本。旧的 `ALB.alb`、`ALB.film`、
`ALB.bearing`、`ALB.thermal`、`ALB.controller`、`ALB.nn`、`ALB.tool`、
`ALB.task`、`ALB.remote` 等平铺模块已经删除，不提供 facade。顶层 `ALB` 只保留版本、
单位制、时步上下文、收敛状态和基础计算块协议；领域实现必须从对应 namespace 显式导入。

机器可读的完整映射位于 `0.2.0_import_map.json`，其中覆盖重构前 65 个 Python 模块和
479 个顶层公共定义，并补充 9 个公共 alias 与 68 个旧根导出的显式映射。两个无运行时价值的
小工具被明确删除，其余定义均有迁移或重命名目标；554 个非删除目标均已通过静态解析检查。

## 计算块生命周期

0.2 的标准计算块遵循同一状态机：

```python
block.input(input_dto)       # 只校验并锁存；旧输出立即失效
block.evaluate()             # 或 solve()/compute_command()/advance()
result = block.output()      # 只读取已完成结果
```

`step(dto)` 只组合以上三步，不提交物理时步。输入尚未计算或输入已改变时，`output()` 抛出
`RuntimeError`。顶层 coupler/workflow 是唯一 `commit_step(StepContext)` 发出者；子模块只能
返回局部 `ConvergenceStatus`。`RossRotor.output()` 不再隐式推进，必须先调用 `advance()`，
当前状态通过 `current_state()` 读取。

`StepCommitLedger` 进一步要求同一 workflow 内 `step_index` 恰好加 1、`dt` 不变且相邻时间差
与 `dt` 一致。`RsRotorBearingCouple` 把时间网格首点作为只读初始快照，只对 `t_list[1:]`
调用 `advance()`；因此包含 `num + 1` 个采样点的网格只发生 `num` 次物理推进。

## 标准 DTO 和单位制

标准端口包括：

- `BearingInput` / `BearingOutput`
- `ControlInput` / `ControlOutput`
- `ValveInput` / `ValveOutput`
- `RotorLoadInput` / `RotorState`

DTO 在构造时验证二维轴向数组、有限性、非负时间和单位制。`UnitSystem` 只允许
`dimensional` 与 `nondimensional`；不存在 `unspecified`。跨单位制调用必须通过显式尺度或
适配器完成，不能依赖调用者猜测。

`ValveOutput.spool` 必须为 `[-1, 1]` 内的有限标量；`NodimCSOrifice.input()` 对越界、非有限或
非标量输入立即失败，并保证失败前后锁存状态不变，不再静默复用上一阀芯位置。

SURROGATE_TRAIN 数据中的 `sx/sy` 是已经归一化的阀芯状态，不是阀输入命令。迁移这类调用时，
使用 `ALB.systems.alb.DirectSpoolBearingInput` 把 `BearingInput` 与 nondimensional
`ValveOutput` 配对，再由 `DirectSpoolBearingBlock.evaluate()` 直接计算；不要先经过
`ValveBlock`，否则会额外引入一次阀动态。

## 结果与持久化

数值模块通过 `result_snapshot()` 返回不可变 `ResultBundle`。文件写入只能由 workflow 注入
`ArtifactWriterProtocol`，写入后返回含相对路径、SHA-256、媒体类型和字节数的
`ArtifactManifest`。

```python
from pathlib import Path

from ALB.infrastructure.persistence import DirectoryArtifactWriter

manifest = result_tree.persist(
    DirectoryArtifactWriter(),
    Path("outputs") / "case_001",
)
```

旧 `SaveTreeNode.save_to_file()`、pickle `save/load` 和数值模块内部 exporter 已删除。旧结果树
只作为纯内存过渡契约存在于 `ALB.contracts.result_tree`。

## 配置迁移

旧 JSON5 不应原地覆盖。使用以下命令读取旧 schema、生成 0.2 schema，并另存到新文件：

```powershell
alb-migrate-config --help
E:/Anaconda2023/envs/ALB/python.exe tools/migrations/migrate_config_0_2.py --help
```

文本默认按 UTF-8 读取。只有 UTF-8 解码失败时才显式警告并临时 fallback 到 GBK/CP936；
fallback 文件如需修改，必须先转换为 UTF-8。

## ALBNN model package 和 scaler

旧 `ALB.nn` pickle 不属于 0.2 运行时兼容面。迁移工具默认不覆盖原文件：

```powershell
alb-migrate-surrogate MODEL SCALER_X SCALER_Y DESTINATION --metadata METADATA --trust-legacy-pickle
E:/Anaconda2023/envs/ALB/python.exe tools/migrations/migrate_surrogate_0_2.py MODEL SCALER_X SCALER_Y DESTINATION --metadata METADATA --trust-legacy-pickle
```

`--trust-legacy-pickle` 是必须显式给出的安全确认，只能用于来源可信的本地 scaler。迁移器仅把
已知 `ALB.nn` scaler 全局映射到 0.2 类并重新序列化；源 model、scaler 和 metadata 均不修改，
目标已存在时仍默认拒绝覆盖。迁移后的 package 加载也必须显式传入 `trust_pickle=True`。

迁移后从 `ALB.surrogate.features`、`networks`、`scalers`、`inference` 和 `package` 显式导入。
调用者必须同时核对输入列顺序、target transform、scaler 类型和 metadata，不能只改 import。

### 发布后 CSOrifice 单调求解修正

CSOrifice 现在把 `q_leak` 明确定义为恒等于 `0.0`。`NodimOrificeConfig`、
`NodimCSOrifice` 和底层 `solve_q()` 对非零泄漏量立即抛出 `ValueError`，不再保留“参数存在但
本轮计算忽略”的模糊状态。若旧调用确实需要泄漏模型，应另行定义有明确流向和压差关系的物理
元件，不能把非零值直接迁入 0.2 CSOrifice。

供油、回油、反向流、供油压力为零和节点负压现在统一消元为公共腔压力 `psv` 的一个连续单调
质量守恒方程。根必定位于外部供油压力与全部节点压力的最小/最大值之间，因此只使用同一个
`brentq` 有界求根，不依赖初值，不按工况切换 `fsolve` 或后备算法。节点流量对节点压力的导数
由该标量方程隐式求导，取代逐列重复求解和矩阵秩判断。

修正继续遵循“先参考、后源码”。commit `765b9b6` 先冻结独立标量预言机的 38 个局部与完整
热耦合数组；下游补充参考再通过同一预言机冻结 ALBSV direct-spool 和 S0011 的 57 个数组。
既有 `full_repo_refactor_v1`、ALBSV v1/v2 和 thermal v2 文件均未覆盖；测试仍校验旧文件完整性，
但 CSOrifice 数值期望由新的 `csorifice_monotonic_reference_v2` 与
`csorifice_monotonic_consumers_reference_v2` 明确接管。

同机比较中，单次 `solve_q` 因输入、物理边界和残差校验增加约 `4.54%` 开销；装配所需 `qdp`
改为隐式解析式后快约 `54.7%`。完整 dimensional+nondimensional 热耦合中，中心工况中位时间
缩短约 `2.07%`，动态工况缩短约 `4.29%`，修正后输出在重复运行中逐元素一致。最终全仓门禁为
`339 passed、13 skipped、1 warning、7 subtests passed`，测试前后 tracked 状态增量为 0；唯一
warning 是既有 `skfuzzy` membership 的零 `sigma` 除法，与本修正无关。
