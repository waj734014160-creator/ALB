# ALB_MAIN 0.2.0 迁移指南

## 文档角色

- 角色：0.1 到 0.2 的稳定破坏式 API 迁移手册。
- 目的：说明新 namespace、计算生命周期、DTO、单位制、持久化和外部调用迁移要求。
- 允许更新：0.2 公共契约、导入映射、迁移工具、已确认不兼容项和稳定验收入口。
- 禁止更新：实时训练/采样状态、论文任务进度、临时日志和未经验证的数值结论。
- 更新节奏：0.2 公共接口、迁移工具或正式验收结论变化时。
- 事实来源：`pyproject.toml`、`ALB/`、`docs/migrations/0.2.0_import_map.json`、
  `docs/migrations/0.2.0_test_map.json`、
  `docs/migrations/0.2.0_external_consumer_audit.json`、
  `docs/migrations/0.2.0_build_acceptance.json`、
  `docs/migrations/0.2.0_release_acceptance.json`、
  `docs/migrations/0.2.0_post_release_rotor_acceptance.json`。

## 迁移结论

`0.2.0` 是命名空间优先的破坏式版本。旧的 `ALB.alb`、`ALB.film`、
`ALB.bearing`、`ALB.thermal`、`ALB.controller`、`ALB.nn`、`ALB.tool`、
`ALB.task`、`ALB.remote` 等平铺模块已经删除，不提供 facade。顶层 `ALB` 只保留版本、
单位制、时步上下文、收敛状态和基础计算块协议；领域实现必须从对应 namespace 显式导入。

机器可读的完整映射位于 `0.2.0_import_map.json`，其中覆盖重构前 65 个 Python 模块和
479 个顶层公共定义，并补充 9 个公共 alias 与 68 个旧根导出的显式映射。两个无运行时价值的
小工具被明确删除，其余定义均有迁移或重命名目标；554 个非删除目标均已通过静态解析检查。

## 计算块生命周期

0.2 的标准计算块遵循同一状态机：

```python
block.input(input_dto)       # 只校验并锁存；旧输出立即失效
block.evaluate()             # 或 solve()/compute_command()/advance()
result = block.output()      # 只读取已完成结果
```

`step(dto)` 只组合以上三步，不提交物理时步。输入尚未计算或输入已改变时，`output()` 抛出
`RuntimeError`。顶层 coupler/workflow 是唯一 `commit_step(StepContext)` 发出者；子模块只能
返回局部 `ConvergenceStatus`。`RossRotor.output()` 不再隐式推进，必须先调用 `advance()`，
当前状态通过 `current_state()` 读取。

## 标准 DTO 和单位制

标准端口包括：

- `BearingInput` / `BearingOutput`
- `ControlInput` / `ControlOutput`
- `ValveInput` / `ValveOutput`
- `RotorLoadInput` / `RotorState`

DTO 在构造时验证二维轴向数组、有限性、非负时间和单位制。`UnitSystem` 只允许
`dimensional` 与 `nondimensional`；不存在 `unspecified`。跨单位制调用必须通过显式尺度或
适配器完成，不能依赖调用者猜测。

## 结果与持久化

数值模块通过 `result_snapshot()` 返回不可变 `ResultBundle`。文件写入只能由 workflow 注入
`ArtifactWriterProtocol`，写入后返回含相对路径、SHA-256、媒体类型和字节数的
`ArtifactManifest`。

```python
from pathlib import Path

from ALB.infrastructure.persistence import DirectoryArtifactWriter

manifest = result_tree.persist(
    DirectoryArtifactWriter(),
    Path("outputs") / "case_001",
)
```

旧 `SaveTreeNode.save_to_file()`、pickle `save/load` 和数值模块内部 exporter 已删除。旧结果树
只作为纯内存过渡契约存在于 `ALB.contracts.result_tree`。

## 配置迁移

旧 JSON5 不应原地覆盖。使用以下命令读取旧 schema、生成 0.2 schema，并另存到新文件：

```powershell
alb-migrate-config --help
E:/Anaconda2023/envs/ALB/python.exe tools/migrations/migrate_config_0_2.py --help
```

文本默认按 UTF-8 读取。只有 UTF-8 解码失败时才显式警告并临时 fallback 到 GBK/CP936；
fallback 文件如需修改，必须先转换为 UTF-8。

## ALBNN model package 和 scaler

旧 `ALB.nn` pickle 不属于 0.2 运行时兼容面。迁移工具默认不覆盖原文件：

```powershell
alb-migrate-surrogate --help
E:/Anaconda2023/envs/ALB/python.exe tools/migrations/migrate_surrogate_0_2.py --help
```

迁移后从 `ALB.surrogate.features`、`networks`、`scalers`、`inference` 和 `package` 显式导入。
调用者必须同时核对输入列顺序、target transform、scaler 类型和 metadata，不能只改 import。

## Optional extras

核心依赖只包含 NumPy、SciPy、pandas、Numba 和 tqdm。领域 extras 为：

- `re-alb[film]`：Matplotlib、scikit-fem。
- `re-alb[control]`：python-control、Matplotlib、scikit-fuzzy。
- `re-alb[dynamics]`：Matplotlib、ROSS。
- `re-alb[surrogate]`：Matplotlib、scikit-learn、PyTorch。
- `re-alb[io]`：JSON5。
- `re-alb[all]`：全部运行时领域依赖。
- `re-alb[test]`：build、import-linter、mypy、pytest。

缺少 optional dependency 时，相关 namespace 会给出对应 extra 和安装命令，不再只暴露原始
`ModuleNotFoundError`。

## 测试迁移和验收

重构前收集的 242 个 pytest 节点均在 `0.2.0_test_map.json` 中有明确替代节点。测试目录为
`tests/unit`、`tests/integration`、`tests/regression`、`tests/validation`；诊断和手动脚本分别位于
`tools/diagnostics` 与 `tools/manual`。`pyproject.toml` 的唯一 `testpaths` 为 `tests`。

数值问题在本轮只报告，不修正；任何数值修正必须另建提交并创建 v2 参考。重构验收继续使用
`refs/full_repo_refactor_v1/` 的不可覆盖精确数组、固定随机种子和性能基线。

主参考仍为 11 个领域、121 个冻结数组。由于原 thermal v1 的残差历史为空且未覆盖自包含
Newton 路径，新增了不覆盖原 v1 的 `refs/full_repo_refactor_addendum_v1/`：它从重构前
commit `a4b2be1` 的隔离源码生成，精确冻结 direct、Newton、transient 三个 case 的 40 个数组，
包括 outer/inner residual、relax、pressure residual offsets 和真实状态提交证据。对应 annotated
tag 为 `full-repo-refactor-thermal-addendum-v1-20260721`。

最终验收为 `293 passed、33 skipped、12 warnings、7 subtests passed`；mypy 2.3.0 对
`ALB/contracts` 与 `ALB/core` 的 19 个源文件报告零问题，测试前后 tracked status 增量为 0。
完整逐节点 skip 原因和命令位于 `0.2.0_release_acceptance.json`。

`v0.2.0` 标签验收时按“只报告、不顺带修正”保留两个已知历史问题：`RossRotor._check_time()` 的错误 `dt` 检查
逻辑，以及旧 S0011 Newton 节点中的 `6.0` lambda 测试构造。后者因外部配置缺失在最终门禁中
明确 skip；自包含 Newton 行为由上述 thermal addendum 覆盖。任何修正都必须使用独立提交和
v2 参考。

### 发布后 S0011 与 liquid-film lambda 修正

2026-07-21 的发布后独立修正没有移动 `v0.2.0` 标签，也没有覆盖任何 v1。先在 commit
`d9d37de` 创建 `thermal_segregated_newton_reference_v2.{json,npz}` 和可复现生成器，再在
commit `afcdc21` 修改测试：

- `test_thermal_segregated_newton.py` 和 `test_thermal_nondim_solver.py` 不再自行使用错误的
  `6.0` 系数，统一从 `FilmNondimScales` 取得液膜 Reynolds bearing number。正确公式为
  `1.5 * miu * omega * l**2 / (ps * c**2)`；旧构造恰好放大 4 倍。
- 三条 S0011 输入、当前解析配置和 fixed-point 配置已嵌入 v2，正式测试不再依赖旧论文路径或
  完整外部 CSV。local exact 与 S0011 exact 分成独立节点，S0011 条件不能再连带屏蔽本地回归。
- 历史 `alb12.json5` 与 CSV 的 SHA-256 仍匹配，但原 S0011 `share.json5` 已不存在；当前
  `share.json5` 哈希不同。因此 v2 的 S0011 数组是“当前代码 + 当前 shared config”回放，
  不是原始 S0011 配置精确重建。
- v1 到 v2 除 nondimensional lambda 修正外还存在不应错误归因的漂移：dimensional small
  force 最大绝对差 `1.277078e-6`；S0011 sample 30、33、162946 的 dimensional force 最大
  绝对差分别为 `30.867843 N`、`332.329049 N`、`35.804397 N`。这些值作为既有参考/配置
  可追溯性问题报告，不在本提交中解释为新的物理修正。

发布后正式门禁为 `297 passed、30 skipped、12 warnings、7 subtests passed`；四个 S0011
节点全部执行并通过，mypy 2.3.0 对 19 个 contracts/core 文件仍为零问题，测试前后 tracked
状态增量为 0。证据位于 `0.2.0_post_release_numeric_acceptance.json`。当前 30 个 skip 分为
`SURROGATE_TRAIN` 17 个和外部 `VALIDATION` 13 个；其中 M0031 的 1 个是 sibling-root 路径
构造错误，其余 29 个是外部旧 namespace 尚未迁移。

S0011 hard-pocket 的局部热不收敛、SciPy “not making good
progress” 警告、非零 orifice cooling/导热覆盖不足和生产尺寸性能则分别属于诊断工况、数值风险
或覆盖边界，目前没有足够证据把它们定性为新的物理方程错误。

同机单线程性能比较已通过。film、thermal、ALB、ALBNN、coupling 的候选/基线中位数比分别为
`0.8943`、`0.9114`、`0.9098`、`0.9028`、`0.9550`，均未超过 `1.15` 暂停阈值；五项在计时前
均通过精确数组门禁。完整样本位于 `0.2.0_performance.json`。

### 发布后 RossRotor 时步修正

RossRotor 修正继续遵守“先参考、后源码”的独立提交顺序：commit `4713eec` 从修正前 commit
`638e4c1` 生成 `ross_rotor_time_validation_reference_v2.{json,npz}`，冻结 global-force 和
node-force 两条合法连续轨迹的 14 个数组；commit `e375d2d` 才修改实现和回归测试。既有 v1
参考和标签均未改动。

`input_force()` 与 `input_force2node()` 现在先调用 `_check_time()`，通过后才追加时间和锁存输入。
校验拒绝非有限时间，以及与系统 `dt` 不一致的提前、重复、倒退或过晚时间；被拒绝的调用不会
改变时间历史、当前/上一载荷、转子状态或 lifecycle ready 标志。合法轨迹继续对 v2 使用
`assert_array_equal`，说明本次只修正校验和失败原子性，没有改变转子离散矩阵或状态推进数值。

正式门禁为 `300 passed、30 skipped、12 warnings、7 subtests passed`；三条 RossRotor
time-validation 节点和四条 S0011 节点全部通过，mypy 2.3.0 对 19 个 contracts/core 文件仍为
零问题，测试前后 tracked 状态增量为 0。证据位于
`0.2.0_post_release_rotor_acceptance.json`。330 个收集节点的摘要和 SHA-256 已同步到
`0.2.0_test_map.json`。
